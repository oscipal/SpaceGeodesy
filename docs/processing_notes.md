### Deviation from the plan: step 12 for `155D_02484_191814`

The plan says to mask the dike-related unwrapping errors through the coherence and loop-closure thresholds, not to fix them, and not to tune thresholds globally. With the default loop threshold (1.5 rad), step 12 rejected all 10 descending interferograms across the 10 Nov 2023 dike (scene loop RMS 2-28 rad) and split the network into three pieces (20231110-20231122, 20231216-20240109), so step 13 bridged the dike step with its smoothness constraint and lost it in every later descending epoch. The loop errors sit at the dike: 54-59 % of the pixels near it fail to close, 3-4 % elsewhere. For this frame only (`licsbas.frame_overrides` in config.yaml), step 12 runs with loop threshold 3.0 rad and `--nullify`: pixels whose loops all exceed pi are set to NaN in each interferogram instead of dropping the whole interferogram, so the dike zone is still masked, but per pixel. The ascending frame keeps the defaults.

Masked by nullify (land pixels, share of each pixel's interferograms in loops): median 12.4%, 95th percentile 42.5%; 1.5% of pixels lost more than half. Effect against GNSS (Stage 6, 14 stations, median whole-series RMS, 1.5 rad run vs this setting, compared on 2026-11-24): descending LOS 87 -> 20 mm, east-west 49 -> 28 mm, vertical 39 -> 31 mm. Near the dike the step is still not recovered (see the known-unreliable values in Stage 4 and 6).

### Re-referencing

LiCSBAS steps 13 and 16 always re-reference `cum`/`vel` to an automatically chosen single pixel (lowest RMS of cum w.r.t. the median, `info/13ref.txt`), wherever it lies; the `120ref.txt` window only sets the reference during the inversion. The exported `cum.h5`/`cum_filt.h5` and `results/vel*` rasters are therefore re-referenced to the mean of the reference window above (exact: one constant per epoch). LiCSBAS's own choice is kept as `refarea_licsbas` in the h5 files.

- `016A_02504_162118/cum.h5`: LiCSBAS ref 472:473/38:39, window pixels valid in all epochs 25/25, velocity offset removed -9.79 mm/yr
- `016A_02504_162118/cum_filt.h5`: LiCSBAS ref 476:477/40:41, window pixels valid in all epochs 25/25, velocity offset removed -9.82 mm/yr
- `155D_02484_191814/cum.h5`: LiCSBAS ref 489:490/87:88, window pixels valid in all epochs 25/25, velocity offset removed 21.16 mm/yr
- `155D_02484_191814/cum_filt.h5`: LiCSBAS ref 93:94/14:15, window pixels valid in all epochs 25/25, velocity offset removed 25.22 mm/yr

Outputs: `results/licsbas/<frame>/` (cum.h5 unfiltered, cum_filt.h5 filtered, results/ rasters as float32 binaries on the grid in EQA.dem_par, info/), QC figures in `figures/qc/<frame>/`. Use cum.h5 (unfiltered) for event-related displacement; step 16 smooths sharp steps.
